# 算法题解析与代码输出规范

当用户要求解析、翻译、讲解算法题，或要求给出思路、题解、代码时，必须遵守以下规范。

## 1. 公式格式（完整、可读、禁止美元符号）

- 展示给用户的任何内容中**禁止出现 `$` 符号**（包括 `$...$` 数学标记、`$1`、`$ARGUMENTS` 等）。
- 公式一律用**纯文本**书写，不用 LaTeX 语法：
  - 例如写：`c[i] = (a[i] + b[i]) mod n`，而不是 `$c_i=(a_i+b_i)\bmod n$`。
- 数学符号使用清晰、无歧义的写法：
  - 小于等于：`<=`；大于等于：`>=`；乘：`*`；除：`/`；
  - 取余：`mod`；异或：`xor`（必要时可写 `^`）；
  - 向下取整：`floor(...)`；向上取整：`ceil(...)`。
- 关键推导步骤必须**完整展开**，每一步单独写清楚，不跳步。
- 多行公式放在代码块中，逐行对齐，保证可读性。
- 变量用下标写法如 `a[i]`、`v[k]`，不要写成难以辨认的 `a_i`。

## 2. 代码规范（只写 C++，简单易懂）

- 只能提供 C++ 代码，必须简单、可读、可直接提交。
- **禁止使用位取反运算符 `~`**，不使用复杂的位运算技巧。
- **禁止使用 lambda 表达式**（如 `[&]` 捕获、`function` 递归 lambda、`auto` 匿名函数）。
- 使用清晰的变量名和常规写法（普通循环、普通函数），必要时加简短中文注释。
- 代码结构完整：包含必要的头文件和 `main()`。

## 3. 讲解风格

- 思路按步骤讲，先讲核心想法，再讲实现细节。
- 给出复杂度（时间、空间）用纯文本说明，例如：`时间复杂度 O(n log n)`。
- 示例数据要能手动验证，并附验证过程。
